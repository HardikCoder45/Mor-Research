# Deep Note — Mixture-of-Recursions: Learning Dynamic Recursive Depths for Adaptive Token-Level Computation

**arXiv:** 2507.10524  
**Paper:** https://arxiv.org/abs/2507.10524  
**PDF:** https://arxiv.org/pdf/2507.10524  
**Local PDF:** `../../papers/seed/2507.10524.pdf`  
**Authors:** Sangmin Bae et al. (KAIST, Mila, Google/DeepMind/Research collaborators)  
**First released:** 2025

## Why this paper is central to the <500M project

MoR is one of the most directly relevant modern architecture papers for the target because it simultaneously attacks three costs that dominate small-model deployment:

1. **Parameter memory:** reuse a shared stack across logical depth.
2. **Compute:** route individual tokens to different recursion depths.
3. **KV-cache / memory traffic:** cache only states required by active tokens, or share first-recursion KVs across recursive depth.

The design is especially relevant because experiments explicitly include **135M and 360M base scales**, not only multi-billion models. It therefore gives actual evidence about when recursion becomes capacity-limited in the size range we care about.

## Core architecture

### Recursive parameter sharing

A standard L-layer Transformer has unique parameters Phi_l at every depth. Recursive Transformers instead reuse a smaller pool of layers multiple times. MoR studies Cycle, Sequence, Middle-Cycle, and Middle-Sequence sharing.

The strongest pattern in the reported ablations is **Middle-Cycle (M-Cyc)**: keep unique first and last layers while cyclically reusing a middle block. This is important because pure sharing makes the embedding-to-feature transition and final readout transformation compete with repeated middle computation. Preserving boundary layers gives the model depth-specific degrees of freedom where they matter most.

**Design implication:** for a <500M model, do not start with one fully tied block repeated N times. Start with unique stem + unique head/tail blocks and tie only the middle stack.

### Dynamic token-level recursion

MoR puts a lightweight router before recursion blocks. Tokens predicted to be difficult receive more recursive passes; easy tokens exit earlier.

Two routing families are studied:

- **Expert-choice:** each recursion depth selects top-k tokens. It guarantees a static global compute budget and excellent load balance, but selection is non-causal during training because top-k is computed across sequence positions; auxiliary routing objectives are required for inference.
- **Token-choice:** each token chooses its final recursion depth. This is causal, but load balance is not guaranteed and requires balancing techniques.

For Nr=3 under balanced allocation, the logical recursion passes process roughly {3/3, 2/3, 1/3} of tokens, so increasingly fewer tokens receive deeper computation.

### KV-cache strategies

MoR introduces two explicit recursion-aware cache designs.

#### Recursion-wise caching
Only tokens active at recursion depth r store K/V states at that level. Attention at that recursion is restricted to locally cached tokens. Under the balanced-capacity approximation, the paper derives total KV memory/IO of roughly `(Nr + 1)/(2 Nr)` relative to storing full KVs for every recursive depth. The scheme also reduces attention FLOPs because the query/key sequence shrinks with depth.

This is the empirically stronger default for the paper's expert-choice router.

#### Recursive KV sharing
Every token computes and caches K/V on the first recursion; subsequent recursive passes reuse that common cache. KV memory drops toward `1/Nr` of a naive depth-specific recursive cache, although all deeper queries still attend the full first-pass sequence.

The paper finds parameter-shared Transformers surprisingly robust to KV sharing because corresponding KV representations across tied depths have similar magnitudes/directions. However, within MoR, KV sharing degrades expert-choice more than recursion-wise caching, while token-choice can benefit because shared full-context KVs compensate for routing errors.

**Design implication:** cache policy and router cannot be chosen independently. A device-oriented architecture should co-design routing granularity with KV semantics.

## Training setup and evidence

The authors pretrain Llama-style decoder-only models from scratch using configurations inspired by SmolLM. Training data is a deduplicated subset of FineWeb-Edu from SmolLM-Corpus. Evaluation uses FineWeb-Edu validation NLL plus six few-shot benchmarks.

### Equal-compute main result

Under a 16.5e18 FLOP budget, the best two-recursion MoR configuration reaches higher average few-shot accuracy than the full vanilla baseline while using nearly half the unique parameters. Its compute efficiency lets it process more tokens under the same FLOP budget.

### Equal-data result

At a fixed 20B training-token budget, MoR-2 reports:
- better validation loss / task accuracy than vanilla and ordinary recursive baselines;
- about **25% fewer training FLOPs**;
- about **19% lower wall-clock training time**;
- about **25% lower peak memory** than the vanilla baseline.

These gains come primarily from hierarchical token filtering and recursion-wise attention, not merely parameter tying.

### Scaling behavior

IsoFLOP experiments span base-model scales of 135M, 360M, 730M, and 1.7B with three recursion steps (therefore roughly one-third unique layer parameters for recursive variants).

Critical result for this project:
- at **135M base scale**, MoR remains below the full vanilla model: recursive capacity is too constrained;
- around **360M and above**, the gap closes and MoR often matches/exceeds vanilla under low/mid compute budgets.

This argues against extreme tying in a very small physical network. Our design should retain enough unique capacity and treat recursion as *additional logical depth*, not a substitute for almost all physical capacity.

### Inference throughput

With continuous depth-wise batching, a 360M-scale experiment reports higher throughput for all MoR depths than vanilla. MoR-4 reaches up to **2.06x throughput** in the maximum-batching setup, with a small likelihood tradeoff. The mechanism relies on parameter sharing so sequences at different logical depths can run the same physical block, while early exits refill compute slots.

**Caveat for phones:** these results are GPU/server batching results. A single-user mobile runtime may not receive the same batching benefit. On-device value comes more directly from lower unique weight bytes, reduced active token compute, and lower cache traffic; actual phone SoC latency must be benchmarked separately.

## Ablations that matter

### Parameter-sharing strategy
Middle-Cycle is consistently strongest among the studied tying schemes, with a widening advantage as size/depth increases. Preserve first/last unique transformations.

### Router design
Expert-choice is materially stronger than token-choice in the main configuration (e.g. 42.6 vs 40.0 average few-shot in one Nr=3 comparison), but it has a deployment problem: the auxiliary objective creates almost binary separation of selected/unselected router scores, making it hard to change top-k capacity at inference.

For an adaptive on-device model, this motivates one of:
- a causal token-choice router with stronger balance regularization;
- budget-conditioned routing trained across multiple capacities;
- calibrated thresholds rather than fixed expert top-k;
- per-request compute-budget conditioning;
- an explicit anytime objective inspired by RecursiveVLM's monotonic-loss idea.

### KV sharing
KV sharing does not universally harm tied Transformers and sometimes behaves like regularization. But the best policy depends on router type. This suggests a useful ablation matrix: `{recursion-wise, first-pass shared, hybrid}` x `{expert-choice, token-choice, budget-conditioned token router}`.

## Latent reasoning and test-time scaling

MoR interprets recursive depth as hidden/latent thinking. Router analysis shows deeper recursion is allocated to less predictable next-token transitions. Increasing the allowed recursion depth improves cumulative log-likelihood within a model, establishing a basic test-time-compute knob.

This is conceptually powerful for a small model: physical memory stays fixed while hard tokens receive more transformations. However, the paper does **not** establish that this produces frontier mathematical reasoning in <500M models after reasoning post-training. The authors explicitly list reasoning-specialized MoR as future work.

## Limitations / confounders

1. **Best evidence is pretraining/perplexity + conventional few-shot**, not full modern reasoning post-training.
2. **Router adaptivity is imperfect:** expert-choice gives better quality but is not naturally flexible at inference after training.
3. **Server GPU throughput != phone latency.** Continuous depth-wise batching may be less useful in single-stream mobile usage.
4. **Aggressive sharing hurts at 135M.** There is a real minimum unique-capacity requirement.
5. **Cache semantics interact with routing.** First-pass KV sharing is not automatically optimal.
6. Training corpus/budget is smaller than modern 2025-2026 tiny-model recipes, so results should be retested after multi-trillion-token training/distillation.
7. Total logical FLOPs can still rise if the router sends many tokens deep; memory efficiency is not free compute.

## Actionable design takeaways

**High-confidence evidence-backed choices**
- Preserve unique boundary layers; share a middle stack (Middle-Cycle family).
- Add token-adaptive depth rather than fixed equal recursion for all tokens.
- Co-design KV policy with routing.
- Train the router during pretraining; avoid purely post-hoc early exit.
- Benchmark at ~350-500M physical sizes because 135M showed capacity bottlenecks.

**Promising project hypotheses**
- Combine M-Cycle recursion with MobileLLM-style deep-thin geometry and GQA.
- Train a **multi-budget, causal router** so a device can select economy/balanced/quality compute without retraining.
- Add an **anytime monotonic loss** across recursion depths so extra loops are statistically encouraged never to reduce token quality.
- Make only the middle block recursive; retain 2-4 unique stem layers and 2-4 unique tail layers.
- Compare recursion-wise caching against shared-first-pass KVs plus low-rank depth adapters.
- Quantize shared recursive weights aggressively (INT4) but initially keep router/norm/embedding sensitive paths at 8/16-bit until ablated.

## Bottom line

MoR is not proof that a recursively tied 500M model will be the strongest possible 500M LM. It *is* strong evidence that **physical parameter count and useful computational depth can be decoupled**, and that the most promising version is not naive looping: it is **boundary-preserving weight sharing + adaptive token depth + cache-aware attention**. For this research program, MoR should be treated as a core architectural primitive and ablation axis, not copied verbatim.
